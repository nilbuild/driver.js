A normal tour points at a button and says "click this", but the user can just press Next without learning anything. Action-driven tours wait for the user to actually do it: type the email, pick the right role, open the menu. If they do something else, they get a hint instead of a dead tour.

Every section below has a live demo. Press **Show me an Example** under it and try doing the wrong thing too.

## Try It

The tour below walks through inviting a teammate. Each step waits for you to do it: type an email, pick a role, send. Click anywhere else, or pick the wrong role, and the tour tells you.

<ActionDrivenSample scenario="invite" client:load>
  ```js
  import { driver } from "driver.js";
  import "driver.js/dist/driver.css";

  const driverObj = driver({
    showButtons: ["close"],
    onInteraction: (element, step, { region, driver }) => {
      if (region !== "outside") {
        return;
      }

      driver.nudge({ description: step.data.hint });
      return false;
    },
    steps: [
      {
        element: "#invite-email",
        advanceOn: {
          event: "keydown",
          when: (element, step, { event, driver }) => {
            if (event.key !== "Enter") {
              return false;
            }

            if (element.checkValidity() && element.value) {
              return true;
            }

            driver.nudge({ description: "That doesn't look like an email address yet." });
            return false;
          },
        },
        data: { hint: "Click the email field and type an address first." },
        popover: { title: "Who are you inviting?", description: "Type an email and press Enter." },
      },
      {
        element: "#invite-role",
        advanceOn: {
          event: "change",
          when: (element, step, { driver }) => {
            if (element.value === "editor") {
              return true;
            }

            driver.nudge({ description: "Only editors can make changes. Choose Editor." });
            return false;
          },
        },
        data: { hint: "Pick a role from the dropdown first." },
        popover: { title: "Pick a role", description: "Choose Editor." },
      },
      {
        element: "#invite-send",
        advanceOn: "click",
        data: { hint: "Click Send invite to finish." },
        popover: { title: "Send it", description: "Click Send invite." },
      },
      {
        element: "#invite-sent",
        waitForElement: 3000,
        popover: { title: "Invite sent", showButtons: ["next"] },
      },
    ],
  });

  driverObj.drive();
  ```
</ActionDrivenSample>


## What You Can Build

| You want to... | Use |
| --- | --- |
| Move on when the user does something | `advanceOn: "change"` |
| Only move on when it's done right | `advanceOn: { event, when }` |
| Move on when your app finishes something | `onHighlighted` + `moveNext()` |
| Block clicks elsewhere and give a hint | `onInteraction` + `nudge()` |
| Let the user use a menu the step opens | `allowedElements` |
| Get back on track when the page changes | `onElementMissing` |

## Move On When Something Happens

Give `advanceOn` an event name and the step completes when that event happens on the highlighted element, like pressing Next. Your own handlers still run first. Flip the switch below to continue.

<ActionDrivenSample scenario="toggle" client:load>
  ```js
  const driverObj = driver({
    showButtons: ["close"],
    steps: [
      {
        element: "#notifications",
        advanceOn: "change",
        popover: { title: "Turn on notifications", description: "Flip the switch." },
      },
      {
        element: "#notifications",
        popover: { title: "Notifications on", showButtons: ["next"] },
      },
    ],
  });

  driverObj.drive();
  ```
</ActionDrivenSample>

Any DOM event works, like `"click"`, `"input"`, `"dblclick"` or `"contextmenu"`. Pass a list to accept any of them: `advanceOn: ["dblclick", "contextmenu"]`.

## Only Move On When It's Right

An event only means something happened, not that it was right. Add `when` to check the result. It runs after your app has handled the event, and the step only completes when it returns `true`. Try picking Team first.

<ActionDrivenSample scenario="plan" client:load>
  ```js
  const driverObj = driver({
    showButtons: ["close"],
    steps: [
      {
        element: "#plan",
        advanceOn: {
          event: "change",
          when: (element, step, { driver }) => {
            if (element.querySelector("input:checked").value === "pro") {
              return true;
            }

            driver.nudge({ description: "That plan has no reports. Pick Pro." });
            return false;
          },
        },
        popover: { title: "Pick a plan", description: "Choose Pro to get reports." },
      },
      { element: "#plan", popover: { title: "Pro it is", showButtons: ["next"] } },
    ],
  });

  driverObj.drive();
  ```
</ActionDrivenSample>

`when` gets the highlighted element, the step and the event, so you can check anything: a field's value, which key was pressed, what the app shows now.

## Move On When Your App Is Done

Sometimes the click is not the end of it: a save has to finish, a request has to come back, a route has to change. Call `driverObj.moveNext()` from your app when it's done. `onHighlighted` gets a `signal` that aborts when the step is left, so your listener cleans itself up. The save below takes a second.

<ActionDrivenSample scenario="save" client:load>
  ```js
  const driverObj = driver({
    showButtons: ["close"],
    steps: [
      {
        element: "#save",
        onHighlighted: (element, step, { signal, driver }) => {
          window.addEventListener("profile-saved", () => driver.moveNext(), { signal });
        },
        popover: { title: "Save your profile", description: "Click Save." },
      },
      {
        element: "#saved",
        waitForElement: 1000,
        popover: { title: "Saved", showButtons: ["next"] },
      },
    ],
  });

  driverObj.drive();
  ```
</ActionDrivenSample>

## Block Wrong Clicks and Give a Hint

`onInteraction` sees every click, right-click and double-click during a step, before your app does. `region` says where it happened: `"element"`, `"allowed"` or `"outside"`. Return `false` to block it. `driverObj.nudge()` shakes the popover, and passing it a change updates the text at the same time. Try right-clicking the file, or clicking somewhere else.

<ActionDrivenSample scenario="feedback" client:load>
  ```js
  const driverObj = driver({
    showButtons: ["close"],
    onInteraction: (element, step, { event, region, driver }) => {
      if (region === "element" && event.type === "contextmenu") {
        driver.nudge({ description: "That was a right-click. Double-click instead." });
        return false;
      }

      if (region === "outside") {
        driver.nudge({ description: "Stay on the file. Double-click it." });
        return false;
      }
    },
    steps: [
      {
        element: "#file",
        advanceOn: "dblclick",
        popover: { title: "Open the file", description: "Double-click report.pdf." },
      },
      {
        element: "#opened",
        waitForElement: 1000,
        popover: { title: "Opened", showButtons: ["next"] },
      },
    ],
  });

  driverObj.drive();
  ```
</ActionDrivenSample>

- A blocked click on the overlay keeps the tour open.
- A double-click is reported as click, click, dblclick, so a double-click step must not block clicks on the element.
- Blocking a click can't undo what your app already did on `pointerdown`, like closing a menu.
- Key presses are not reported, so typing always works.
- `driverObj.updatePopover()` changes the popover without the shake. Calling it without arguments restores the original.

## Let the User Use a Menu

When the action opens something outside the highlighted element, like a menu or a dropdown, list it in `allowedElements` so the user can use it. Elements that appear later are picked up automatically. In the demo, the menu is usable, Delete is blocked, and pressing Escape or clicking More again closes the menu and sends you back a step.

<ActionDrivenSample scenario="menu" client:load>
  ```js
  const driverObj = driver({
    showButtons: ["close"],
    onInteraction: (element, step, { event, region, driver }) => {
      if (event.target.closest("[data-action=delete]")) {
        driver.nudge({ description: "Not Delete. Choose Archive." });
        return false;
      }

      if (region === "outside") {
        driver.nudge({ description: step.data.hint });
        return false;
      }
    },
    onElementMissing: (element, step, { cause, driver }) => {
      if (cause === "removed") {
        driver.movePrevious();
        driver.updatePopover({ description: "The menu closed. Click More to open it again." });
      }
    },
    steps: [
      {
        element: "#more",
        advanceOn: "click",
        allowedElements: ".menu",
        data: { hint: "Click More to open the menu." },
        popover: { title: "Open the menu", description: "Click More." },
      },
      {
        element: ".menu [data-action=archive]",
        waitForElement: 500,
        advanceOn: "click",
        allowedElements: [".menu", "#more"],
        data: { hint: "Choose Archive from the menu." },
        popover: { title: "Archive it", description: "Choose Archive." },
      },
      {
        element: "#archived",
        waitForElement: 1000,
        popover: { title: "Archived", showButtons: ["next"] },
      },
    ],
  });

  driverObj.drive();
  ```
</ActionDrivenSample>

`onElementMissing` runs with `cause: "removed"` when the highlighted element leaves the page. With `waitForElement` set, it first waits that long for the element to come back. While the hook is set, the tour also follows an element that your framework re-renders.

If the menu sits below the overlay, target its positioned wrapper or set `--driver-allowed-z-index`.

## Recover From a Slow Load

When a step's `waitForElement` runs out, `onElementMissing` runs with `cause: "timeout"`, before the usual fallback popover. Return `false` to keep the user on the current step so they can try again. The first load below is slow on purpose.

<ActionDrivenSample scenario="load" client:load>
  ```js
  const driverObj = driver({
    showButtons: ["close"],
    onElementMissing: (element, step, { cause, driver }) => {
      if (cause === "timeout") {
        driver.nudge({ description: "Still loading. Click Load report again." });
        return false;
      }
    },
    steps: [
      {
        element: "#load",
        advanceOn: "click",
        popover: { title: "Load the report", description: "Click Load report." },
      },
      {
        element: "#report",
        waitForElement: 1500,
        popover: { title: "Loaded", showButtons: ["next"] },
      },
    ],
  });

  driverObj.drive();
  ```
</ActionDrivenSample>

> **Tip**: Always leave a way out, like the close button. iOS Safari never fires `contextmenu`, so if a step waits for a right-click, accept another event too.
