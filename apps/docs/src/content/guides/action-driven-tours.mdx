Training flows teach by doing. Each step waits for the user to perform the action it describes, everything else is blocked, and a wrong action gets a hint. Driver.js gives you the building blocks; your app decides what counts as right or wrong.

## Try It

The tour below walks through inviting a teammate. Each step waits for you to do it: type an email, pick a role, send. Click anywhere else, or pick the wrong role, and the tour tells you.

<ActionDrivenSample client:load>
  ```js
  import { driver } from "driver.js";
  import "driver.js/dist/driver.css";

  const driverObj = driver({
    showButtons: ["close"],
    allowKeyboardControl: false,
    overlayClickBehavior: "none",
    onInteraction: (element, step, { event, region, driver }) => {
      if (event.type === "keydown" || region !== "outside") {
        return;
      }

      driver.updatePopover({ description: step.data.hint });
      driver.nudge();
      return false;
    },
    steps: [
      {
        element: "#invite-email",
        advanceOn: (element, step, { next, signal }) => {
          element.addEventListener("keydown", event => {
            if (event.key === "Enter" && element.checkValidity() && element.value) {
              next();
            }
          }, { signal });
        },
        data: { hint: "Click the email field and type an address first." },
        popover: { title: "Who are you inviting?", description: "Type an email and press Enter." },
      },
      {
        element: "#invite-role",
        advanceOn: (element, step, { next, signal, driver }) => {
          element.addEventListener("change", () => {
            if (element.value === "editor") {
              next();
              return;
            }

            driver.updatePopover({ description: "Viewers can only look around. Choose Editor." });
            driver.nudge();
          }, { signal });
        },
        data: { hint: "Pick a role from the dropdown first." },
        popover: { title: "Pick a role", description: "Choose Editor." },
      },
      {
        element: "#invite-send",
        advanceOn: "click",
        data: { hint: "Click Send invite to finish." },
        popover: { title: "Send it", description: "Click Send invite." },
      },
      {
        element: "#invite-sent",
        waitForElement: 3000,
        popover: { title: "Invite sent", showButtons: ["next"] },
      },
    ],
  });

  driverObj.drive();
  ```
</ActionDrivenSample>

## Complete a Step with `advanceOn`

Give `advanceOn` an event name and the step completes when that event happens on the highlighted element. It behaves like pressing Next, and your own handlers still run.

```js
{ element: "#invite-send", advanceOn: "click" }
{ element: "#file", advanceOn: ["dblclick", "contextmenu"] } // either one
```

An event only means the action happened, not that it succeeded. When completion depends on your app, pass a function and call `next()` yourself. Listeners using `signal` are removed when the step is left.

```js
{
  element: "#invite-email",
  advanceOn: (element, step, { next, signal }) => {
    element.addEventListener("keydown", event => {
      if (event.key === "Enter" && element.checkValidity() && element.value) {
        next();
      }
    }, { signal });
  },
}
```

## Block Wrong Actions with `onInteraction`

`onInteraction` sees every click, right-click, double-click and key press during a step, before your app does. `region` says where it happened: `"element"`, `"allowed"` or `"outside"`. Return `false` to block it.

```js
onInteraction: (element, step, { event, region }) => {
  if (region === "outside" && event.type !== "keydown") {
    return false;
  }
},
```

- A double-click is reported as click, click, dblclick, so a double-click step must not reject clicks.
- Don't block keys. That also blocks browser and screen reader shortcuts.

## Allow a Menu with `allowedElements`

When the action opens something outside the highlighted element, like a context menu or dropdown, list it in `allowedElements` to make it usable. Elements that appear later are picked up automatically.

```js
{
  element: ".menu [data-action=rename]",
  allowedElements: [".menu", "#file"],
}
```

If the menu still sits below the overlay, target its positioned wrapper or set `--driver-allowed-z-index`.

## Give Feedback with `updatePopover` and `nudge`

`driverObj.updatePopover()` changes the visible popover in place, and calling it without arguments restores the original. `driverObj.nudge()` shakes the popover.

```js
driverObj.updatePopover({ description: "Viewers can only look around. Choose Editor." });
driverObj.nudge();
```

## Recover with `onElementMissing`

Sometimes the target goes away, like a menu closed with Escape. `onElementMissing` runs with `cause: "removed"` when the highlighted element leaves the page, or `cause: "timeout"` when the next step's `waitForElement` runs out.

```js
onElementMissing: (element, step, { cause, driver }) => {
  if (cause === "removed") {
    driver.movePrevious();
    driver.updatePopover({ description: "The menu closed. Right-click the file again." });
  }
},
```

> **Tip**: Always leave a way out, like the close button. iOS Safari never fires `contextmenu`, so if a step waits for a right-click, accept another event too or use a function `advanceOn`.
