Training flows teach by doing. Each step waits for the user to perform the action it describes, clicks elsewhere can be blocked, and a wrong action gets a hint. Driver.js gives you the building blocks; your app decides what counts as right or wrong.

## Try It

The tour below walks through inviting a teammate. Each step waits for you to do it: type an email, pick a role, send. Click anywhere else, or pick the wrong role, and the tour tells you.

<ActionDrivenSample client:load>
  ```js
  import { driver } from "driver.js";
  import "driver.js/dist/driver.css";

  const driverObj = driver({
    showButtons: ["close"],
    onInteraction: (element, step, { region, driver }) => {
      if (region !== "outside") {
        return;
      }

      driver.nudge({ description: step.data.hint });
      return false;
    },
    steps: [
      {
        element: "#invite-email",
        advanceOn: {
          event: "keydown",
          when: (element, step, { event, driver }) => {
            if (event.key !== "Enter") {
              return false;
            }

            if (element.checkValidity() && element.value) {
              return true;
            }

            driver.nudge({ description: "That doesn't look like an email address yet." });
            return false;
          },
        },
        data: { hint: "Click the email field and type an address first." },
        popover: { title: "Who are you inviting?", description: "Type an email and press Enter." },
      },
      {
        element: "#invite-role",
        advanceOn: {
          event: "change",
          when: (element, step, { driver }) => {
            if (element.value === "editor") {
              return true;
            }

            driver.nudge({ description: "Only editors can make changes. Choose Editor." });
            return false;
          },
        },
        data: { hint: "Pick a role from the dropdown first." },
        popover: { title: "Pick a role", description: "Choose Editor." },
      },
      {
        element: "#invite-send",
        advanceOn: "click",
        data: { hint: "Click Send invite to finish." },
        popover: { title: "Send it", description: "Click Send invite." },
      },
      {
        element: "#invite-sent",
        waitForElement: 3000,
        popover: { title: "Invite sent", showButtons: ["next"] },
      },
    ],
  });

  driverObj.drive();
  ```
</ActionDrivenSample>

## Complete a Step with `advanceOn`

Give `advanceOn` an event name and the step completes when that event happens on the highlighted element. It behaves like pressing Next, and your own handlers still run first.

```js
{ element: "#invite-send", advanceOn: "click" }
{ element: "#file", advanceOn: ["dblclick", "contextmenu"] } // either one
```

An event only means the action happened, not that it succeeded. Add `when` to check the result. It runs after your app has handled the event, and the step only completes when it returns `true`.

```js
{
  element: "#invite-role",
  advanceOn: {
    event: "change",
    when: (element, step, { event }) => element.value === "editor",
  },
}
```

Only events on the highlighted element count, not on `allowedElements`. When completion depends on something else, like a save finishing or a route change, call `driverObj.moveNext()` from your app. `onHighlighted` gets a `signal` that aborts when the step is left, so listeners clean themselves up:

```js
onHighlighted: (element, step, { signal }) => {
  window.addEventListener("invite-saved", () => driverObj.moveNext(), { signal });
},
```

## Block Clicks with `onInteraction`

`onInteraction` sees every click, right-click and double-click during a step, before your app does. `region` says where it happened: `"element"`, `"allowed"` or `"outside"`. Return `false` to block it.

```js
onInteraction: (element, step, { region }) => {
  if (region === "outside") {
    return false;
  }
},
```

- A blocked click on the overlay keeps the tour open.
- A double-click is reported as click, click, dblclick, so a double-click step must not reject clicks.
- Blocking a click can't undo what your app already did on `pointerdown`, like closing a menu.
- Key presses are not reported, so typing always works.

## Allow a Menu with `allowedElements`

When the action opens something outside the highlighted element, like a context menu or dropdown, list it in `allowedElements` to make it usable. Elements that appear later are picked up automatically.

```js
{
  element: ".menu [data-action=rename]",
  allowedElements: [".menu", "#file"],
}
```

If the menu still sits below the overlay, target its positioned wrapper or set `--driver-allowed-z-index`.

## Give Feedback with `nudge`

`driverObj.nudge()` shakes the popover. Pass it a change to update the popover at the same time. `driverObj.updatePopover()` changes the popover without the shake, and calling it without arguments restores the original.

```js
driverObj.nudge({ description: "Only editors can make changes. Choose Editor." });
```

## Recover with `onElementMissing`

Sometimes the target goes away, like a menu closed with Escape. `onElementMissing` runs with `cause: "removed"` when the highlighted element leaves the page.

```js
onElementMissing: (element, step, { cause, driver }) => {
  if (cause === "removed") {
    driver.movePrevious();
    driver.updatePopover({ description: "The menu closed. Right-click the file again." });
  }
},
```

It also runs with `cause: "timeout"` when a step's `waitForElement` runs out, before the usual fallback. Return `false` to keep the user on the current step instead. While the hook is set, the tour also follows a highlighted element that your framework re-renders.

> **Tip**: Always leave a way out, like the close button. iOS Safari never fires `contextmenu`, so if a step waits for a right-click, accept another event too.
